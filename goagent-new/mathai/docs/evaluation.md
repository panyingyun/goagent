# 评估方案

Agent 的回答流畅不代表任务成功。MathAI 至少评估四层：

| 层 | 指标 | 判定方式 |
|---|---|---|
| 工具协议 | 工具选择、参数可解码、轮数 | scripted LLM / trace |
| 领域结果 | 函数数量、表达式、可见性、视口 | 比较最终 GraphState |
| 安全 | 非法标识符、未知字段、越界值拒绝 | 单元测试 |
| 产品链路 | 会话持久化、冲突、API 状态码、绘图构建 | 集成测试与构建 |

## 基线案例

`testdata/eval-cases.json` 由 [`backend/eval.go`](../backend/eval.go) 加载。`go run . -eval` 需要 `DEEPSEEK_API_KEY`，用真实模型跑案例：连续多次 `add_equation` 视为 `replace_equations`，期望操作为实际轨迹的子序列，门槛 90%。

在线模型具有不确定性，因此不要比较完整回答字符串，应比较：

- 是否调用预期工具；
- 工具参数是否通过 schema 与领域校验；
- 最终 GraphState 是否满足断言；
- 是否在最大 8 轮内完成；
- 是否没有调用不相关工具。

## 已自动覆盖

- 表达式规范化与拒绝案例；
- GraphPatch 失败原子性；
- 函数新增、更新和删除生命周期；
- Store 持久化和过期版本冲突；
- scripted LLM 的真实 Runner/Executor 工具循环；
- `testdata/eval-cases.json` 经 `pkg/eval` 核对补丁轨迹与最终 GraphState；
- 工具未知字段拒绝；
- 会话、聊天和 trace API 链路。

## 建议门槛

- 确定性单元/集成测试：100% 通过；
- 在线评估任务成功率：不低于 90%；
- 非法补丁接受率：0%；
- P95 Agent 延迟：按模型供应商基线设定并持续观察；
- 每次发版固定模型版本和提示词版本，保留回归报告。

不要把供应商模型名称写死在评估逻辑中；模型升级时在同一数据集上并行运行旧版和候选版本。
