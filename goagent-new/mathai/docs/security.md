# 安全设计与边界

## 已实现

- **原生工具协议**：不从 assistant 普通文本中解析动作；
- **严格 JSON**：HTTP 与写工具都拒绝未知字段和多个 JSON 值；
- **表达式白名单**：只允许一元函数所需字符和标识符，强制显式乘法；
- **原子领域操作**：补丁在副本上完成全部校验，失败不产生部分更新；
- **副作用策略**：`apply_graph_patch` 标记为 write，由限定 Approver 批准；
- **资源限制**：32 KiB 请求体、4000 字消息、12 条函数、4000 个采样点、视口范围上限；
- **并发保护**：版本条件提交，避免 lost update；
- **HTTP 防护**：可选 Bearer token、精确 CORS origin、限流、读写超时和优雅关闭；
- **前端求值**：使用 mathjs 受限表达式，不使用 `eval` 或 `new Function`；
- **容器**：非 root、只读根文件系统、`no-new-privileges`、数据专用卷。

## 威胁模型

用户消息可能包含提示注入；模型返回的工具参数也不可信。提示词只帮助模型遵守协议，真正安全边界是严格 decoder、领域验证、工具副作用元数据和存储提交条件。

此案例不让模型访问文件系统、URL、Shell、数据库查询或密钥，因此图形工具无法把提示注入升级为宿主机操作。

## 生产环境还需增加

- 在反向代理或 API Gateway 做 TLS、分布式限流和身份认证；
- 为用户和 Session 建立所有权关系，不能只靠一个共享 Token；
- 将 API Token 存在 HttpOnly 会话中，而不是浏览器 localStorage；
- 把日志和 trace 中的内容按隐私策略脱敏并设置 TTL；
- 使用数据库事务支持多副本，并对数据卷做备份；
- 对 LLM 供应商设置地区、数据保留和预算策略；
- 增加 CSP、`frame-ancestors` 等安全响应头；
- 定期更新前端依赖并执行依赖漏洞扫描。

## 已知限制

JSON Store 只支持单进程；进程内限流不适合多副本；Trace Store 非持久化；表达式白名单不等价于完整数学语法证明；前端 localStorage Token 只适合本地教学。
